# 功能架构：KOSX 影响力社区（信息架构 + 页面功能树）

> 用途：站点的整体功能架构——从最外层菜单到每一层页面，以及背后的设计原则。
> 改版、加模块、加页面时先看这份文档，保持结构一致。
>
> 维护：顶层菜单或页面职责变化时同步更新本文件；README 的 Roadmap 与之对齐。

## 定位

KOSX 影响力社区（impact.kosx.ai）不是一份普通的榜单，而是一座**影响力社区**：
每位成员被看见、想关注的人能找到值得关注的博主、KOSX 的能量被更多人看见。
全部数据收敛在 X 一个平台，基于两个能力：SocialData（结构化时序数据）+ Grok（判断/总结/监控）。

## 设计原则

1. **实体做页**：只有真正有"一摊数据"的对象才开页面。核心实体 = 成员、帖子（声量数据量还小，先挂总览，量大了再升格）。
2. **维度做筛，不滥开页**：赛道有"货架 + 排行"语义所以开页；标签几十个、会涨、无排行语义，永远只做筛子（广场筛选、成员详情 chips、赛道聚合、首页热点）。
3. **视图做榜，一套组件多处出口**：总排行 / 成长榜 / 新锐潜力榜 / 影响力榜 / 登阶记录 / 赛道成员榜，本质是同一个排行组件的不同切片，区别只在「按什么指标排 × 时间档 × 是否限定赛道」。共用一套行样式，靠 URL 串起不同视图，不重复建模。
4. **报告做盘，覆盖三种场景**：成员周报（个人盘，晒自己）、社群日报（社群盘，晒活跃，按日期归档产内容与 SEO）、社群能量报告（社群盘，晒全景）。

## 与线上现状的关系

- **已上线**：① 总览（除今日动态/赛道速览/内容热点摘要外）、② 榜单四榜、③ 成员广场/详情/周报、④ 赛道索引/详情、⑤ 精华帖 + 内容洞察、⑥ 关于、搜索、成员卡/赛道卡/周报卡分享。
- **待做（[新] 标注）**：见 README「Roadmap」，五个方向（看见当下 / 看见彼此 / 看见自己 / 看见价值 / 打牢底座）逐项落地，落地后在本文档把 [新] 移除、在 README 勾选。

## 刻意不做

- 标签不做独立页面（只做筛子）
- 单条帖子不开三级页（直接跳 X 原文）
- 不接多平台（只做 X）
- 不做变现杂项（付费群 / 广告横幅）
