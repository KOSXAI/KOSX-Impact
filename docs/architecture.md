# 功能架构：KOSX 影响力社区（信息架构 + 页面功能树）

> 用途：站点的整体功能架构——从最外层菜单到每一层页面，以及背后的设计原则。
> 改版、加模块、加页面时先看这份文档，保持结构一致。
>
> 维护：顶层菜单或页面职责变化时同步更新本文件；README 的 Roadmap 与之对齐。

## 定位

KOSX 影响力社区（impact.kosx.ai）不是一份普通的榜单，而是一座**影响力社区**：
每位成员被看见、想关注的人能找到值得关注的博主、KOSX 的能量被更多人看见。
全部数据收敛在 X 一个平台，基于 SocialData（结构化时序数据）+ 本地分析脚本（判断/总结/监控）。

## 设计原则

1. **门少屋深**：一级菜单只保留「独立进入心智」——访客只带着三个问题来：这个社群怎么样（首页）、有谁值得关注（博主）、他们产出什么（内容）。菜单项数 = 心智数，不等于页面数；URL / SEO / 分享链接不依赖导航，页面可以深藏。
2. **实体做页**：只有真正有"一摊数据"的对象才开页面。核心实体 = 成员（导航词叫「博主」、站内文案叫「成员」：导航用陌生人的词，站内用身份的词）、帖子；声量数据量还小，先挂首页，量大了再升格。
3. **维度做筛，不滥开页**：赛道有"货架 + 排行"语义所以开页；标签几十个、会涨、无排行语义，永远只做筛子（广场筛选、成员详情 chips、赛道聚合、首页热点）。
4. **视图做榜，一套组件多处出口**：总排行 / 成长榜 / 新锐潜力榜 / 影响力榜 / 被提及榜 / 登阶记录 / 赛道成员榜，本质是同一个排行组件的不同切片，区别只在「按什么指标排 × 时间档 × 是否限定赛道」。共用一套行样式，靠 URL 串起不同视图，不重复建模。
5. **报告做盘，覆盖三种场景**：成员周报（个人盘，晒自己）、社群日报（社群盘，晒活跃，按日期归档产内容与 SEO）、社群能量报告（社群盘，晒全景）。

## 顶层菜单

顶栏三项：**首页 / 博主 / 内容**——320px 全放得下，无汉堡、无渐进隐藏；
页脚：**关于 / 官网 / GitHub / 加入追踪**（不动）。
激活态规则：`/` 与 `/daily` 高亮「首页」；`/leaderboard`、`/members`、`/tracks` 及其子路由高亮「博主」。

## 与线上现状的关系

- **导航改版已上线**（2026-09-08）：三项顶栏（首页 / 博主 / 内容）+ 博主模块内三视图切换（榜单 / 广场 / 赛道）；所有 URL（`/leaderboard`、`/tracks/:slug`、`/members/:id`、`/reports/:memberId`）与 SEO 全部保留。
- **已上线**：社群规模卡 / 社群全景（称号分布·总量趋势）/ 四榜 / 广场筛选 / 赛道索引与详情 / 精华帖 / 内容洞察 / 成员详情 / 周报 / 粉丝画像 / 相似账号 / 品牌声量列表 / 搜索（成员+赛道）/ 分享卡。
- **待做（树中 [新] 标注）**：见 README「Roadmap」五个方向；落地后在本文档把 [新] 移除、在 README 勾选。

## 刻意不做

- 标签不做独立页面（只做筛子）
- 单条帖子不开三级页（直接跳 X 原文）
- 不接多平台（只做 X）
- 不做变现杂项（付费群 / 广告横幅）
